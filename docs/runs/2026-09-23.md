## Judgment calls
- F2c's line carries no explicit DoD, so I read "same approach" as F2b's DoD:
  the renderer against a synthetic template, with the object and loader
  isolation already covered by the shared flavor-profile tables and their tests.
- The renderer takes a plain `RecordSheet`/`RecordLine` object and does no DB
  access, like `Flavor`. Activity, Overage and the active/excipient split aren't
  in the DB, so they're render-time inputs the caller supplies — not invented or
  stored, so nothing fabricates a classification.
- No app UI this pass. A "Download Sample Record Sheet" button needs a home for
  the per-sample inputs the flavor sheet doesn't collect (Activity, Overage,
  active/excipient split, scoop size, servings/unit, jar/lid) — its own task,
  and building it now would exceed the smallest change meeting the DoD. Flagged
  in the PR, not half-built. No Backlog entries added.
