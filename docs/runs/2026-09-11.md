## What I did

Scoped and planned E5; wrote no implementation. The brief was KISS and YAGNI,
so most of the work was deciding what the task is *not*: no link table and no
load-time link resolution (both loaders full-reload, so a stored link buys
nothing at a few hundred rows and needs invalidating every run), no parser for
the lab's three location formats (its own task, and depending on it would
stall this one — the string is shown verbatim), no third search tab, and no
second copy of the material page's stock panel inside the lab tab.

The match rule is E2's, already decided and documented, with one rule added:
a four-character floor on the sample-code fallback, because a two-character
code is a substring of half the warehouse and a wrong link is fabricated data.
Real codes are 5–7 digits, so it excludes nothing real. The DoD requires a
test pinning it, plus a Part # match, a substring match, a sample matching
nothing, and a code matching two materials.

Written into the task as a hard constraint: no existing query, loader or table
changes, and both new blocks must render quietly when `lab_samples` is empty —
which is every CI run, since the synthetic sheet has no lab catalog.

### Correction, same session

The design above was reviewed and reversed before merge. E5 is now a **new
Warehouse + Lab tab** with one search across both tables, and the two existing
lookup tabs are left untouched — not the "Also in the lab" / "Also in the
warehouse" blocks described above.

The blocks had a blind spot that the review caught: a lab-only sample has no
material row, so searching Material lookup for it finds nothing and the block
never renders. That design could only answer "warehouse, lab, or both?" for
someone who already knew which of the two to start in. Everything else in the
task — the match rule, the four-character floor, the read-time join, no
location parser — carried over unchanged.

lookup tab". Same branch, same PR number.
