# 2026-10-12 (interactive)

**Outcome:** The All Materials Lookup box now suggests matches as you type, like Warehouse Lookup, and no search box caps its suggestions. PR opened from branch `combined-searchbox`.

## What I did
- `ui/combined_tab.py`: the text box + results table became an `st_searchbox`. Each suggestion is labelled `Warehouse: / Lab: / Both: <part # — name>`; picking one shows that row's summary. A pick that no longer exists (database rebuilt under an open page) gets a warning, not a crash.
- `dtf_materials/queries.py`: `search_materials`, `search_lab_samples` and `search_warehouse_and_lab` default to no limit (`limit=None` binds `-1`); a caller can still pass one.
- `ui/material_tab.py`: dropped the `limit=10` on the Warehouse Lookup suggestions.
- Tests: the smoke test that typed into the old text box is gone (AppTest can't drive the component); `test_queries.py` gains option-label and uncapped-search tests. `python -m pytest -q`: all pass.
- Checked in the browser on port 8502: typing "mango" lists every match, picking a Both row renders its summary.

## Judgment calls
- Supersedes the 2026-09-12 call "one results table, not a searchbox-and-detail view". User's call: same control as Warehouse Lookup, show every suggestion.
- The option value is the whole combined-search result dict, not an id, because a Both row needs both ids.
- `.claude/launch.json` added for the in-app preview (port 8502; 8501 was already in use by another Streamlit).
